# Clase 012: PRIMARY KEY

**Resumen**: `PRIMARY KEY` es la restricción que identifica de forma única cada fila de una tabla. Exige unicidad y ausencia de `NULL`, y PostgreSQL la implementa con un índice único interno llamado `<tabla>_pkey`.

**Objetivo**: declarar la clave primaria de una tabla para que cada fila quede identificada de forma única.

## Concepto

`PRIMARY KEY` es la restricción que marca la columna, o la combinación de columnas, que identifica cada fila. Exige a la vez unicidad y ausencia de `NULL`.

PostgreSQL la hace cumplir con un índice único interno llamado `<tabla>_pkey`. Una tabla puede tener una sola `PRIMARY KEY`, pero esa clave puede estar formada por varias columnas: es la **clave compuesta**.

## Utilidad en análisis de datos

1. **Catálogo de artículos**: el código de artículo evita filas duplicadas al cargar planillas externas.
2. **Registro de asistencia**: la pareja `(empleado, fecha)` garantiza una sola marca por día y persona.
3. **Conciliación de pagos**: el `id` de pago permite cruzar el sistema contable con el operativo sin contar dos veces.

## Sintaxis general

```sql
CREATE TABLE tabla (
    columna   tipo PRIMARY KEY,                       -- clave de una sola columna
    otra      tipo,
    CONSTRAINT nombre_pk PRIMARY KEY (col1, col2)     -- clave compuesta y con nombre propio
);
```

- **PRIMARY KEY**: restricción de unicidad y `NOT NULL` sobre las columnas indicadas.
- **CONSTRAINT nombre_pk**: le da un nombre legible a la restricción. Si se omite, PostgreSQL usa `<tabla>_pkey`.

## Ejemplos

### Ejemplo 1: clave de una columna

```sql
CREATE TABLE clientes (
    id_cliente INTEGER PRIMARY KEY,
    nombre     VARCHAR(60) NOT NULL,
    ciudad     VARCHAR(40)
);
```

Datos que tendría la tabla:

| id_cliente | nombre | ciudad |
| ---------- | ------ | ------ |
| 1          | Ana    | Lima   |
| 2          | Beto   | Cusco  |
| 3          | Carla  | `NULL` |

`SELECT * FROM clientes;` devuelve exactamente esas 3 filas.

Si se intenta cargar otro `id_cliente = 2`:

- `ERROR: duplicate key value violates unique constraint "clientes_pkey"`

Si se intenta cargar `id_cliente` sin valor:

- `ERROR: null value in column "id_cliente" violates not-null constraint`

Es decir, la `PRIMARY KEY` ya rechaza `NULL`, aunque no se haya escrito `NOT NULL` en la columna. La columna `ciudad` sí admite `NULL` porque no forma parte de la clave.

### Ejemplo 2: clave compuesta

```sql
CREATE TABLE inscripciones (
    id_socio  INTEGER,
    id_taller INTEGER,
    CONSTRAINT pk_inscripciones PRIMARY KEY (id_socio, id_taller)
);
```

Datos válidos:

| id_socio | id_taller |
| -------- | --------- |
| 1        | 10        |
| 1        | 20        |
| 2        | 10        |

La pareja `(1, 10)` no puede repetirse, pero el socio 1 sí puede aparecer en varios talleres: la unicidad se evalúa sobre la combinación, no sobre cada columna por separado.

Un segundo intento de `(1, 10)` produce:

- `ERROR: duplicate key value violates unique constraint "pk_inscripciones"`

### Ejemplo 3: clave con nombre sobre una sola columna

```sql
CREATE TABLE salas (
    codigo CHAR(3),
    nombre VARCHAR(40) NOT NULL,
    CONSTRAINT pk_salas PRIMARY KEY (codigo)
);
```

En DBeaver, al abrir la tabla en el editor, en la pestaña DDL o Propiedades, se ve que `codigo` quedó como `NOT NULL` y que existe la restricción `pk_salas`.

Nombrar la restricción ayuda cuando hay que leer mensajes de error en cargas grandes: el nombre dice de inmediato qué regla se rompió.

## Cuándo conviene cada forma

| Forma                          | Cuándo usarla                                                   | Ejemplos                             |
| ------------------------------ | --------------------------------------------------------------- | ------------------------------------ |
| Clave de una columna           | Existe un identificador estable y corto                         | `id_cliente`, código de sala         |
| Clave compuesta                | La fila solo tiene sentido como combinación                     | socio + taller; sala + fecha + turno |
| Evitar datos mutables o largos | Si el valor cambia, hay que actualizar la clave en todas partes | correo, teléfono, nombre completo    |

Evita usar como clave datos que cambian o son largos, como correo, teléfono o nombre completo.

## Errores y buenas prácticas

- Dos `PRIMARY KEY` en la misma tabla producen el error `multiple primary keys for table ... are not allowed`: la tabla admite una sola clave primaria.
- Repetir la misma columna dentro de la clave produce el error `column ... appears twice in primary key constraint`: la lista de columnas debe ser distinta.
- Crear la tabla sin `PRIMARY KEY` no da error, pero después nada impide filas idénticas y los conteos dejan de ser confiables.
- Nombra la restricción como `pk_<tabla>` cuando sea compuesta: los mensajes de error se vuelven legibles.
- Prefiere claves cortas, estables y sin significado de negocio; deja los datos mutables en columnas comunes.
