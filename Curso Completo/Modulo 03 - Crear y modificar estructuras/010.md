# Clase 010: CREATE TABLE

**Objetivo**: crear una tabla nueva definiendo sus columnas y el tipo de dato de cada una.

**Concepto**: `CREATE TABLE` es una sentencia DDL (lenguaje de definición de datos) que registra una tabla vacía dentro del esquema activo. Cada columna necesita un nombre y un tipo; las restricciones (`NOT NULL`, `PRIMARY KEY`, `CHECK`...) llegan en las clases 011 a 016. La tabla nace sin filas: los datos se cargan después con `INSERT` (clase 021).

## Para qué sirve en análisis de datos

- Modelar un dominio nuevo (clientes, pedidos, sensores) antes de poblarlo.
- Crear tablas de paso donde guardar resultados intermedios de un análisis.
- Armar tablas de práctica para validar tipos y estructuras antes de un diseño final.

## Sintaxis general

```sql
CREATE TABLE [IF NOT EXISTS] nombre_tabla (
    columna1 TIPO,
    columna2 TIPO,
    ...
);
```

- `IF NOT EXISTS`: si la tabla ya existe, no hace nada en lugar de lanzar error.
- `nombre_tabla`: identificador. Sin comillas, PostgreSQL lo guarda en minúsculas.
- `TIPO`: obligatorio en cada columna (`INTEGER`, `VARCHAR(50)`, `DATE`, `BOOLEAN`, `NUMERIC`...).
- La coma separa columnas; la última columna no lleva coma.

El nombre de la tabla y de las columnas conviene escribirlo en minúsculas, sin acentos ni espacios. Si se usan comillas dobles, el nombre queda sensible a mayúsculas y hay que citarlo siempre igual.

## Ejemplos

### Ejemplo 1: tabla mínima de cuatro columnas

```sql
CREATE TABLE libros (
    id_libro INTEGER,
    titulo VARCHAR(120),
    anio INTEGER,
    disponible BOOLEAN
);

SELECT * FROM libros;
```

Resultado: la tabla existe pero está vacía. Tiene 0 filas y las columnas `id_libro`, `titulo`, `anio` y `disponible`.

### Ejemplo 2: elegir el tipo correcto para cada dato

```sql
CREATE TABLE sensores (
    id_sensor INTEGER,
    nombre TEXT,
    temperatura REAL,
    presion NUMERIC(6,2),
    activo BOOLEAN,
    ultima_lectura TIMESTAMP
);
```

- `NUMERIC(6,2)` admite hasta `9999.99` con dos decimales exactos.
- `TIMESTAMP` guarda fecha y hora en un solo campo, como en `ultima_lectura`.
- `TEXT` no tiene límite práctico de longitud; `VARCHAR(n)` sí lo tiene.

```sql
SELECT * FROM sensores;
```

Resultado: la tabla existe pero está vacía. Tiene 0 filas y las columnas `id_sensor`, `nombre`, `temperatura`, `presion`, `activo` y `ultima_lectura`.

### Ejemplo 3: IF NOT EXISTS evita el error al reejecutar el script

```sql
CREATE TABLE IF NOT EXISTS turnos (
    id_turno INTEGER,
    empleado VARCHAR(60),
    fecha DATE,
    hora_inicio TIME,
    cubierto BOOLEAN
);
```

Al ejecutarlo por segunda vez aparece un aviso, no un error:

`NOTICE: relation "turnos" already exists, skipping`

Sin `IF NOT EXISTS`, la segunda ejecución falla:

`ERROR: relation "turnos" already exists`

### Ejemplo 4: comillas dobles y nombres con mayúsculas o espacios

```sql
CREATE TABLE "Pedidos" (
    "IdPedido" INTEGER,
    "Fecha Pedido" DATE,
    total NUMERIC(10,2)
);
```

La tabla se llamará exactamente `"Pedidos"` (con P mayúscula) y habrá que citarla siempre:

```sql
SELECT * FROM "Pedidos";
```

`SELECT * FROM Pedidos;` devuelve `ERROR: relation "pedidos" does not exist`.

En cambio, `total` va sin comillas porque no las necesita.

> Después de crear una tabla, refresca la conexión en DBeaver con `F5` para verla en el navegador de bases de datos, dentro de `Esquemas > practica > Tablas`.

## Errores y buenas prácticas

- Omitir el tipo de una columna: `CREATE TABLE t (a);` devuelve `ERROR: syntax error at or near ")"`. Toda columna necesita nombre y tipo.
- Repetir el nombre de una columna: `ERROR: column "x" specified more than once`.
- Reejecutar sin `IF NOT EXISTS`: `ERROR: relation "tabla" already exists`.
- Usa minúsculas, sin acentos ni espacios: evitas tener que citar cada nombre.
- Ajusta el tipo al dato: `NUMERIC` para dinero, `DATE`/`TIMESTAMP` para fechas, `VARCHAR(n)` solo cuando la longitud máxima esté clara.
