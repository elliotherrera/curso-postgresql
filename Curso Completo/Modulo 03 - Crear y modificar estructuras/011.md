# Clase 011: NOT NULL y DEFAULT

## Resumen

Esta clase explica cómo usar `NOT NULL` para impedir valores nulos y `DEFAULT` para asignar un valor cuando la columna se omite en un `INSERT`. Ambas restricciones son independientes y complementarias.

## Conceptos clave

- **`NOT NULL`**: restricción de columna que rechaza cualquier `NULL`.
- **`DEFAULT`**: expresión que PostgreSQL usa cuando la columna se omite al cargar una fila.

Son independientes: un `DEFAULT` no impide que alguien inserte `NULL` explícito, y `NOT NULL` no aporta ningún valor por sí solo.

### Utilidad en análisis de datos

1. Garantizar que las claves de negocio (`documento`, `código`, `email`) siempre tengan valor, para que los cruces y conteos no pierdan filas.
2. Evitar que columnas de estado (`activo`, `entregado`, `nivel`) queden en `NULL` y rompan los filtros booleanos o los `CASE WHEN` posteriores.
3. Ahorrar trabajo repetitivo en la carga: fecha de alta, país, moneda o cantidad inicial se completan solos cuando no se indican.

## Sintaxis general

```sql
CREATE TABLE nombre_tabla (
  columna  TIPO  [NOT NULL]  [DEFAULT valor]  [, ...]
);
```

- `NOT NULL`: rechaza `NULL` en esa columna.
- `DEFAULT valor`: valor que se usa si la columna no aparece en el `INSERT`.

El orden entre `NOT NULL` y `DEFAULT` es libre; ambos son opcionales.

## Ejemplos

### Ejemplo 1: lo mínimo

```sql
CREATE TABLE teoria_socios (
  id_socio   INTEGER      NOT NULL,
  nombre     VARCHAR(60)  NOT NULL,
  correo     VARCHAR(120),
  activo     BOOLEAN      NOT NULL DEFAULT TRUE,
  categoria  VARCHAR(20)  NOT NULL DEFAULT 'general',
  puntos     INTEGER      DEFAULT 0
);
```

Estructura resultante (pestaña Propiedades / DDL de DBeaver):

| Columna     | Tipo           | Admite `NULL` | Valor por defecto |
| ----------- | -------------- | ------------- | ----------------- |
| `id_socio`  | `integer`      | no            | -                 |
| `nombre`    | `varchar(60)`  | no            | -                 |
| `correo`    | `varchar(120)` | sí            | -                 |
| `activo`    | `boolean`      | no            | `true`            |
| `categoria` | `varchar(20)`  | no            | `'general'`       |
| `puntos`    | `integer`      | sí            | `0`               |

Lectura: `correo` puede quedar vacío; `activo` y `categoria` no, y si se omiten toman `TRUE` y `'general'`. `puntos` es opcional pero arranca en `0`.

### Ejemplo 2: el orden de las palabras clave no importa

```sql
CREATE TABLE teoria_reservas (
  id_reserva  INTEGER       NOT NULL,
  fecha       DATE          NOT NULL DEFAULT '2025-01-01',
  personas    SMALLINT      DEFAULT 2 NOT NULL,
  salon       VARCHAR(30)   NOT NULL DEFAULT 'sin asignar',
  observacion TEXT
);
```

| Columna       | Tipo          | Admite `NULL` | Valor por defecto |
| ------------- | ------------- | ------------- | ----------------- |
| `id_reserva`  | `integer`     | no            | -                 |
| `fecha`       | `date`        | no            | `'2025-01-01'`    |
| `personas`    | `smallint`    | no            | `2`               |
| `salon`       | `varchar(30)` | no            | `'sin asignar'`   |
| `observacion` | `text`        | sí            | -                 |

`personas` demuestra que `DEFAULT` puede escribirse antes o después de `NOT NULL`: el efecto es el mismo (valor por defecto `2` y prohibido el `NULL`).

### Ejemplo 3: DEFAULT no es lo mismo que NOT NULL

```sql
CREATE TABLE teoria_notas (
  id_nota    INTEGER   NOT NULL,
  detalle    TEXT      DEFAULT 'sin detalle',
  prioridad  SMALLINT  DEFAULT 3 NOT NULL
);
```

En `detalle`: si la columna se omite se guarda `'sin detalle'`, pero si alguien escribe `NULL` de forma explícita, se guarda `NULL` (la columna lo admite).

En `prioridad`: omitirla da `3`, y un `NULL` explícito se rechaza con `null value in column "prioridad" violates not-null constraint`.

> Moraleja: para blindar una columna hacen falta las dos cosas, o solo `NOT NULL` si no quieres valor por defecto.

## Errores y buenas prácticas

### Errores comunes

- Escribir la restricción antes del tipo: `nombre NOT NULL VARCHAR(50)` produce `ERROR: syntax error at or near "VARCHAR"`; el tipo debe ir primero.
- `DEFAULT` incompatible con el tipo: `precio NUMERIC(8,2) DEFAULT 'gratis'` produce `ERROR: invalid input syntax for type numeric: "gratis"`.
- Error silencioso: `CHAR(5) DEFAULT 'pendiente'` crea la tabla sin avisar, pero el valor queda truncado a `'pendi'`.

### Buenas prácticas

- Si el dato no se conoce, deja la columna nulable; un `DEFAULT` inventado (`'sin correo'`, `0` en un sueldo) contamina promedios y conteos.
- Declara `NOT NULL` en toda columna que uses en filtros, cálculos o claves de negocio, para que los `NULL` no aparezcan recién en el análisis.
